# ADR-017: painel web local em container (Core + FastAPI)

- **Status:** Aceito (11/11/2026), por decisão do responsável. PR B (UI + `forge_frontend`) na mesma decisão.
- **Data:** 2026-11-11.
- **Relaciona:** ADR-004 (Postgres), ADR-005 (segredos fora do Git), ADR-013 (sandbox de agentes), ADR-014 (auth humana), ADR-015 (Cursor CLI / gh).

## Contexto

O Core já persiste em Postgres, autentica pessoas por device flow na CLI e rascunha issues com Cursor CLI + gh. O painel local sobe Core + API JSON + UI estática no Compose `forge`.

## Decisões

- **D1. Runtime.** O Core e a API JSON rodam no serviço `forge_backend` da imagem `deploy/web/Dockerfile`. Distinto do sandbox de agentes (ADR-013 / FRG-6): o filho do orquestrador continua `--network none`, descartável, sem Docker socket. O backend do painel tem egresso para `github.com` / `api.github.com` (device flow, `gh`) e para os hosts da Cursor CLI. Um worker uvicorn (`workers=1`) porque o device flow pendente vive em memória. A imagem declara `USER forge` (uid 1000). O entrypoint ainda tem o ramo root+chown para volume antigo se o processo nascer como root.
- **D2. Compose.** Arquivo `docker-compose.forge.yml`, `name: forge`. Serviços com `container_name` igual: `forge_postgres`, `forge_backend`, `forge_frontend`. `forge_frontend` é nginx unprivileged (imagem pinada por digest), UI estática e reverse-proxy de `/api/` para `forge_backend:8091`, origem única no navegador em `127.0.0.1:8090`. O `docker-compose.yml` legado não é alterado na função; só marcado como legado. `docker-compose.dev.yml` permanece para testes manuais (ADR-004) e **conflita na 5433** com o padrão deste compose.
- **D3. Interface.** Extra opcional `[web]`: FastAPI, uvicorn. Testes do Core sem `[web]` não precisam dessas libs. API só JSON sob `/api/`. Sem HTML no backend. A UI é HTML + JS vanilla (sem framework, sem script inline; CSP `default-src 'self'`).
- **D4. Bind e publicação.** Dentro da rede compose o backend escuta `0.0.0.0:8091` para o proxy alcançar. **No host, o backend não publica 8091** (a 8091 ficou só no hop interno). Frontend: `127.0.0.1:${FORGE_FRONTEND_HOST_PORT:-8090}:8080`. Postgres: `127.0.0.1:${FORGE_PG_HOST_PORT:-5433}:5432`. Nunca `0.0.0.0`.
- **D5. Host e proxy.** Allowlist de `Host`: `127.0.0.1:8090`, `localhost:8090`, `127.0.0.1:8091`, `localhost:8091` (configurável; 8091 permanece para testes diretos da API). Sem CORS. `X-Forwarded-*` só é lido se `FORGE_TRUST_FORWARDED=true` **e** o peer está em `FORGE_TRUSTED_PROXIES` (IP ou hostname resolvido, no compose `forge_frontend`). O nginx envia `Host`/`X-Forwarded-*` com `127.0.0.1:8090`.
- **D6. Sessão e CSRF.** Cookie `forge_session`: HttpOnly, SameSite=Strict, Path=/, Secure configurável (desligado em HTTP local). CSRF double-submit: cookie legível `forge_csrf` + cabeçalho `X-CSRF-Token` em todo não-GET. O token CSRF nasce **uma vez** por pedido (`request.state.csrf_token`) e o `Set-Cookie` reutiliza esse valor. Device flow pendente: id opaco HttpOnly atado ao navegador, estado só em memória, TTL. Token GitHub só em memória, descartado depois de `/user`; no banco só `token_hash`. Sessão web e CLI têm `expires_at` (padrão 7 dias, `FORGE_SESSION_TTL_SECONDS`). Renovação deslizante: se restar menos da metade do prazo, um INSERT em `session_renewals` (append-only; `sessions` não recebe UPDATE). Logout grava `session_revocations` e apaga cookies de sessão/device com os mesmos atributos (`path=/`, `SameSite=strict`, `HttpOnly`, `Secure` configurável). Owner **não** implica editor.
- **D7. Segredos e papéis.** Postgres continua com Compose `secrets` `environment:` (`FORGE_PG_OWNER_PASSWORD`, `FORGE_PG_APP_PASSWORD`, `FORGE_PG_READONLY_PASSWORD`) e `POSTGRES_PASSWORD_FILE`. O `forge_backend` é `read_only: true`; Compose v2 recusa `secrets.environment` nesse caso (`file is the sole supported option`). **Plano B:** tmpfs em `/run/secrets` (mode 0700, uid/gid 1000) e o entrypoint lê as senhas da env, grava arquivos 0600 no tmpfs e **remove as variáveis do processo** antes do exec do uvicorn. O código continua lendo de arquivo. Nenhuma senha em arquivo do host. Residual: `docker inspect` ainda mostra a env configurada no serviço. URLs de banco montadas em runtime a partir dos arquivos; falha fechado se faltar. A CLI `python -m forge_core.auth.cli` **também** aplica esses arquivos quando `FORGE_SECRET_*_PASSWORD_FILE` está no ambiente (caso do `docker compose exec forge_backend`). Fora do container a URL continua obrigatória. Não se imprime URL nem senha. Três papéis: `forge_owner` (migrações), `forge_app` (menor privilégio, `postgres_roles.sql`), `forge_readonly` (SELECT; em `sessions` sem `token_hash`; sem INSERT/UPDATE/DELETE/DDL). O leitor **é criado no primeiro boot**; senha ausente ou vazia **falha fechado**. SQLite só em testes/CI.
- **D8. CLIs.** `gh` (2.81.0) e Cursor Agent (`2026.11.10-731fb78`) instalados **na imagem**, com SHA-256. Login uma vez dentro do container (`docker compose exec forge_backend gh auth login -s project` / `gh auth refresh -s project` / `cursor-agent login`), como usuário `forge`. Credenciais no volume nomeado `forge_cli_home` (`HOME` do usuário `forge`). O `gh` grava o token em texto puro nesse volume; risco aceito (volume Docker próprio, nunca montar keyring/`HOME` do host). Sem mount de keyring/HOME/APPDATA/`~/.config/gh` do host, sem `docker.sock`, sem `GH_TOKEN`/`GITHUB_TOKEN`. Allowlist de env (ADR-015) e `--mode ask` + temp dir continuam.
- **D9. Semente e tarefas.** Projeto `FORGE` e cinco repositórios da org `ferreiraeborzone`, idempotente. `list_active_allowed_repos` devolve só `provider=github`, owner `ferreiraeborzone` (case-insensitive) e `repo_name` em `ALLOWED_REPOS`. A tela gera rascunho via `DraftService.generate` (adaptador Cursor CLI no backend), guarda em `drafts` (`rascunho` → `confirmado` → `publicado`), publica com `DraftService.publish` / `load_resume` (idempotente; não duplica issue) e grava `task_links` (`issue`, `branch`, `pr` se o `gh` achar). Confirm recusa `preview_hash` diferente (`diff_changed`). Sem upload de imagem. Contexto ≤ 64 KiB.

## Alternativas

| Opção | Por que não |
| --- | --- |
| Bind 127.0.0.1 *dentro* do container | O `forge_frontend` na rede compose não alcançaria o backend. |
| Publicar 8091 no host além do 8090 | Duas origens; cookie Path=/ serviria as duas. A 8091 ficou só interna. |
| Confiar em `X-Forwarded-*` de qualquer peer | A allowlist de Host aceitaria valor forjado. |
| Papel leitor opcional se a senha faltar | Inconsistente com falha fechada dos outros segredos. |
| HTML no backend | A UI mora no `forge_frontend`; o backend é API JSON. |

## Consequências

Quem opera sobe um compose, entra pelo device flow no navegador em `http://127.0.0.1:8090` e usa HeidiSQL/DBeaver no loopback com `forge_readonly` (`drafts` e `task_links`). Risco residual aceito: credenciais CLI no volume Docker (não no keyring do SO); o backend tem egresso para GitHub e Cursor; `board_item_id` só é gravado se conhecido no INSERT do vínculo `issue` (sem UPDATE em `task_links`). O sandbox de agentes não muda.
